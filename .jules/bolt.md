## 2026-08-10 - Set-based Path Preserves and Memoized Key Conversions
**Learning:** Object key notation conversion (e.g., camelCase <=> snakeCase) recursively traverses deeply nested trees and checks path exceptions (preserveKeys). Using an array linear scan (`.includes()`) for path exceptions on every property of every node results in $O(N)$ lookup complexity where $N$ is the length of path exceptions. Converting this array once to a `Set` simplifies lookup to $O(1)$. Furthermore, regular expression operations (like `key.replace()`) on repetitive key names can be completely bypassed by keeping a simple Map-based lookup cache.
**Action:** Always verify if repeatedly checked path collections can be mapped to Set-based lookup tables, and memoize string/regex conversions on repetitive keys/identifiers.
