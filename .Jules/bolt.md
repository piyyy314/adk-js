## 2026-09-11 - Optimize Recursive Object Notation Conversions
**Learning:** Checking `Array.prototype.includes()` and building path strings (`parentKey + '.' + key`) during recursive object conversions (`toCamelCase`/`toSnakeCase`) introduces $O(N \times K)$ complexity and string allocation overhead for every property. Using a `Set` for key preservation lookups, bypassing path concatenation when no preserve keys exist, and adding fast-path checks (`key.includes('_')` and `/[A-Z]/.test(key)`) before regex replacements significantly improves performance during event payload transformations.
**Action:** Always use pre-instantiated `Set`s for path/key matching in recursive converters, skip path creation when set is empty, and check strings for target characters before executing regular expression replaces.
